# 本機資料櫃設計筆記

## 目標

本功能不是新增一套取代各處室資料模型的中央資料庫，而是替既有
`localStorage`／`sessionStorage` 提供可發現、可攜、可檢查與可銷毀的
統一檔案目錄。各模組仍負責自己的版本遷移與業務規則；資料櫃只保存
原始字串，避免匯入時擅自改寫舊格式。

## 檔案範圍

- 只管理 `tu:` 命名空間，不觸碰同來源下其他網站程式或瀏覽器資料。
- 五十個已知鍵按身分、招生、課業、圖書館、校園生活、研究、介面、
  事件帳本與反面檔案分類。
- 執行時仍掃描全部 `tu:` 鍵；未登錄的新鍵會進入「未登錄卷宗」，
  防止後續功能留下不可見資料。
- 反面檔案只有在實際存在時才顯示，避免資料櫃本身提前洩漏隱藏校區。

## 可見範圍

- `localStorage`：目前瀏覽器設定檔與 GitHub Pages 來源可見，關閉分頁
  後仍保留。
- 介面書籤：同樣保存在本機，但只包含語言、導覽入口與最後位置。
- 反面檔案：技術上仍在本機來源內，產品上必須明確說明不會進入正式
  學籍或 `tu:campus:ledger`。
- `sessionStorage`：只限目前分頁工作階段。現有唯一項目是
  `tu:phantasm:pass`，可查看、可刪除但不可匯出或匯入。

## 空間計算

資料櫃以鍵名與值的 UTF-8 byte 數計算本校卷宗占用，這是可重現的精確
數字。介面另以常見 5 MiB localStorage 配額作參考尺，並在瀏覽器支援
`navigator.storage.estimate()` 時顯示來源整體估算；後者可能包含其他
儲存，所以兩者不可混稱為同一數字。

## 封箱格式

匯出格式為 `touhou-university-on-device-archive` version 1：

- `exportedAt` 與來源只作檔案說明；
- `records` 保存 key、storage 與未轉換的 raw string；
- 最後以 Web Crypto SHA-256 對前述完整 payload 加封；
- 短時／不可攜資料在封箱前排除。

匯入先驗證總大小、JSON、格式版本、卷宗數、鍵名命名空間、重複鍵、
storage 類型、單筆大小與 SHA-256，全部通過後才寫入。預設跳過目前
已存在的同名卷宗；使用者明確選擇後才覆蓋。任何 quota 寫入錯誤都要
把本次已改動鍵回滾到原值。

## 幻想鄉語氣

阿求負責目錄與來源欄，荷取負責河童封箱機，銷毀動作用靈夢式紅印。
封印只證明封箱後未改動，不替封箱前內容的真實性背書；這既是完整性
模型，也保留魔理沙材料來源與文花帖標題的校園摩擦。
